## 8. GitHub Pages: cấu hình triển khai

### 8.1. Vite base path

Nếu repository tên `my-portfolio`, cấu hình:

``` ts
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import tailwindcss from '@tailwindcss/vite'

export default defineConfig({
  plugins: [react(), tailwindcss()],
  base: '/my-portfolio/',
})
```

Nếu repository tên `USERNAME.github.io`, dùng `base: '/'`.

Không hardcode đường dẫn tuyệt đối cho asset trong source nếu điều đó
làm hỏng project subpath. Ưu tiên asset import hoặc
`import.meta.env.BASE_URL` khi cần.

### 8.2. GitHub Actions workflow mẫu

Tạo `.github/workflows/deploy.yml`:

``` yaml
name: Deploy Portfolio to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm

      - name: Install dependencies
        run: npm ci

      - name: Build
        run: npm run build

      - name: Upload artifact
        uses: actions/upload-pages-artifact@v4
        with:
          path: ./dist

  deploy:
    needs: build
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - name: Deploy
        id: deployment
        uses: actions/deploy-pages@v4
```

Lưu ý: - Kiểm tra phiên bản action và Node LTS phù hợp tại thời điểm
chạy. - Nếu dùng `npm ci`, phải commit `package-lock.json`. - Trong
Settings → Pages, chọn GitHub Actions làm deployment source. - Không đưa
secret/API key vào repository. - Nếu có custom domain, cấu hình DNS và
HTTPS theo tài liệu GitHub.

## 9. SEO, Performance và Quality Gate

### SEO

-   Title rõ ràng: `Trương Thiện Thư | IT Student Portfolio`.
-   Meta description mô tả đúng nội dung.
-   Open Graph title, description, image.
-   Favicon.
-   Heading semantic.
-   Alt text.
-   URL dễ đọc.
-   Không nhồi nhét từ khóa.

### Performance

-   Dùng WebP/AVIF khi phù hợp.
-   Đặt width/height hoặc aspect ratio cho ảnh để hạn chế layout shift.
-   Lazy-load ảnh dưới fold.
-   Không lazy-load ảnh Hero quan trọng nếu gây chậm hiển thị.
-   Tối ưu font và chỉ tải weight cần thiết.
-   Hạn chế animation nặng.
-   Chia nhỏ component khi thực sự cần thiết.

### Quality Gate đề xuất

-   `npm run build` phải thành công.
-   Không có lỗi JavaScript nghiêm trọng trong console.
-   Không có link nội bộ bị hỏng.
-   Không có nút giả hoặc form giả.
-   Không có horizontal overflow ở viewport mobile phổ biến.
-   Lighthouse mục tiêu: Performance, Accessibility, Best Practices, SEO
    đều hướng tới 90+ nếu điều kiện đo cho phép; đây là mục tiêu, không
    được giả mạo điểm số.
-   Kiểm tra ít nhất ở mobile khoảng 375px, tablet khoảng 768px và
    desktop khoảng 1440px.

## 12. Hướng dẫn thực thi dành riêng cho Antigravity

Hãy thực hiện theo thứ tự sau:

1.  **Đọc toàn bộ tài liệu này trước khi sửa code.**
2.  Kiểm tra workspace/repository hiện tại và liệt kê các file đang có.
    Không xóa hoặc ghi đè dữ liệu hiện hữu nếu chưa hiểu mục đích.
3.  Nếu workspace trống, khởi tạo dự án theo stack đề xuất. Nếu đã có dự
    án phù hợp, tận dụng cấu trúc hiện tại thay vì tạo lại không cần
    thiết.
4.  Trước khi code, đưa ra một kế hoạch ngắn gồm: cấu trúc thư mục, các
    component, dependencies và các placeholder cần người dùng cung cấp.
5.  Xây dựng website hoàn chỉnh theo yêu cầu, ưu tiên chất lượng giao
    diện và responsive.
6.  Dùng dữ liệu cá nhân và dự án trong tài liệu này. Không tự tạo
    email, social URL, repository URL, ảnh cá nhân, CV hoặc thành tích.
7.  Những trường chưa có dữ liệu phải gom vào các file data dễ chỉnh
    sửa, dùng `TODO` rõ ràng và ghi trong README.
8.  Không tạo nút Demo/GitHub trỏ tới `#`, URL giả hoặc form báo gửi
    thành công khi chưa gửi thật.
9.  Sau khi lập trình, chạy các lệnh kiểm tra phù hợp, tối thiểu là cài
    dependencies và `npm run build`. Nếu có lint/typecheck thì chạy
    thêm.
10. Tự sửa các lỗi phát hiện được trước khi báo hoàn thành.
11. Tạo workflow GitHub Actions và cấu hình Vite cho GitHub Pages. Dùng
    placeholder cho username/repository nếu chưa biết; giải thích chính
    xác chỗ cần thay.
12. Không tự push lên GitHub, tạo repository từ tài khoản người dùng
    hoặc thay đổi cài đặt tài khoản nếu chưa được người dùng cho phép.
13. Cuối cùng, báo cáo:
    -   Những gì đã xây dựng.
    -   Cấu trúc file chính.
    -   Công nghệ và dependencies.
    -   Kết quả build/test thực tế.
    -   Những thông tin người dùng cần bổ sung.
    -   Các bước deploy GitHub Pages.
    -   Những giới hạn hoặc việc chưa hoàn thành.
